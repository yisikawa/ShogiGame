# USIエンジン対戦エラー修正報告

## 概要
USIエンジンとの対戦中に発生していたエラー `移動元に駒が存在しません` の修正を行いました。
対局が20手目付近まで進んだところで、クライアントとUSIエンジンの間で盤面の認識にズレ（Desync）が生じ、進行不能になる問題を解決しました。

## 原因
**クライアント側のAI（中級）が「自殺手（王手放置）」を選択していたこと**が主原因でした。

1. **AIのバグ**: クライアントのAIが、自玉を相手の駒が利いている場所に移動させる本来「反則」となる手を生成しました。
2. **チェック漏れ**: クライアント側でその手を「有効」として処理し、盤面を更新してしまいました。
3. **認識のズレ**: その不正な手の履歴をUSIエンジンに送信した結果、正規のルールを持つエンジン側との内部状態に不整合が発生。以降のエンジンの指し手が、クライアント側の盤面と一致せずエラーとなりました。

## 修正内容

### 1. 合法手チェックの厳格化 (`isMoveSafe`)
`game.js` に実装されている移動可能範囲の計算処理において、以下のチェックを追加しました。
*   駒の動きとして正しいか（従来のチェック）
*   **その手を指した後、自玉が王手状態にならないか（追加したチェック）**

これにより、AIおよび人間のプレイヤーは、自殺手や王手放置となる手を選択できなくなりました。

### 2. 無限ループの修正
王手判定（`isInCheck`）の実装において、再帰的な呼び出しによる無限ループを防ぐため、判定ロジックを修正しました。
*   **修正前**: `isInCheck` -> `getAllPossibleMoves` (ここで再度 `isInCheck` が呼ばれる) -> 無限ループ
*   **修正後**: `isInCheck` -> `getAllPseudoPossibleMoves` (王手チェックを含まない純粋な移動範囲のみ計算) -> ループ解消

## 検証結果
*   **テスト環境**: USIサーバー（Port 8082, YaneuraOu） vs AI中級
*   **結果**: 以前エラーが発生していた20手目を越えて、終局まで正常に対局が進行することを確認しました。
